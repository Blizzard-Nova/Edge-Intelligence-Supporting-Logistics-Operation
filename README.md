# Edge Intelligence Supporting Logistics Operation

Supply chain delays cause major financial losses. This project uses machine learning to identify high-risk routes, giving operators a targeted, data-driven framework to strategically invest in IoT infrastructure, reduce delays, and protect profits.

The work has two parts:

1. **Delay prediction.** Classification models predict whether an order will be delivered late, based on where it ships from and to and how it ships.
2. **IoT investment simulation.** Loss-making routes are mapped, and several IoT scenarios (from basic GPS tracking to a full IoT suite) are simulated to estimate how many routes could become profitable.

## Repository Contents

| `Supply_chain_work_in_progress.ipynb` | Data cleaning, route profitability analysis, anomaly detection, and delay-classification models (Random Forest, XGBoost) with feature selection, tuning, cross-validation, and SHAP |

The `.html` maps are generated by the notebooks with Folium. Download and open them in a browser to explore them.

## Methodology

### 1. Route profitability analysis

- A `delay_days` metric is computed as real minus scheduled shipping days, clipped at zero.
- Orders are grouped into routes (customer state/city, order region/state/city, shipping mode), optionally broken down by product category, department, and customer segment.
- For each route the notebook computes order count, total and mean profit, late rate, and 90th-percentile delay.
- Routes with enough volume are ranked by profit to surface the worst performers.
- Anomalies are flagged with an interquartile-range fence on mean profit and a hard threshold on late rate (above 95%). Routes that trip both are marked as "double anomalies".

### 2. Delay classification

- **Target:** `is_delayed`, which is 1 when `delay_days > 0`.
- **Preprocessing:** `First Class` shipments are dropped (24,840 to 21,016 rows, with delay rate falling from 57.35% to 49.59%). Features are encoded, then split 80/20 (16,812 train, 4,204 test).
- **Models:** Random Forest and XGBoost, with class balancing.
- **Feature selection:** Permutation importance reduces the feature set from 17 to 8: customer city and state, order city, state and region, and shipping mode.
- **Tuning and validation:** `RandomizedSearchCV` (30 iterations, 5-fold CV, weighted F1), followed by stratified 5-fold cross-validation and SHAP analysis of the XGBoost model.
- **Sanity checks:** Logistic regression as a linear baseline, delay-rate-by-feature plots, and a PCA plot to check linear separability.

### 3. IoT scenario simulation

Applied to the loss-making `First Class` routes. Each scenario assumes a proportional reduction in late rate and P90 delay:

| Scenario | Assumed delay reduction |
| -------- | ----------------------- |
| No IoT (baseline) | 0% |
| Basic GPS tracking | 25% |
| GPS + Predictive Maintenance | 40% |
| Full IoT Suite | 55% |

Other assumptions: IoT cost of **$2.50 per shipment** and a **$15 penalty per late delivery**. The simulation estimates profit recovered, IoT cost, and which routes flip to profitable.

## Results

### Delay prediction (held-out test set)

| Model | Test accuracy | Weighted F1 |
| ----- | ------------- | ----------- |
| Logistic Regression (baseline) | 0.683 | 0.681 |
| Random Forest (tuned) | 0.810 | about 0.810 |
| XGBoost (tuned) | 0.819 | 0.819 |

Five-fold cross-validated weighted F1 is 0.801 for Random Forest and 0.804 for XGBoost, with standard deviations under 0.01. The large gap over logistic regression suggests the relationship between location, shipping mode, and delays is strongly non-linear.

### IoT simulation (208 loss-making First Class routes)

| Scenario | Routes turned profitable | Total profit delta |
| -------- | ------------------------ | ------------------ |
| No IoT (baseline) | 0 | -$41,197 |
| Basic GPS tracking | 1 | -$40,264 |
| GPS + Predictive Maintenance | 6 | -$39,705 |
| Full IoT Suite | 10 (4.8%) | -$39,145 |

Even under the most optimistic scenario, only a small share of routes become profitable and the total remains negative. This supports a **targeted** investment strategy over blanket deployment: IoT spending is best focused on the specific high-risk routes the models and anomaly analysis identify.

## Getting Started

### Requirements

- Python 3.9 or newer
- Jupyter Notebook or JupyterLab

Libraries used: `pandas`, `numpy`, `matplotlib`, `seaborn`, `scikit-learn`, `xgboost`, `shap`, `scipy`, `tabulate`, `folium`, `pgeocode`

### Installation

```bash
git clone https://github.com/Blizzard-Nova/Edge-Intelligence-Supporting-Logistics-Operation.git
cd Edge-Intelligence-Supporting-Logistics-Operation

pip install pandas numpy matplotlib seaborn scikit-learn xgboost shap scipy tabulate folium pgeocode jupyter
```

### Running the notebooks

1. Add the data files listed above to the repository root.
2. Launch Jupyter:
   ```bash
   jupyter notebook
   ```
3. Run `IoT Simulation.ipynb`. It reads the CSVs from the working directory and regenerates the HTML maps.
4. Run `Supply_chain_work_in_progress.ipynb` for the modeling work. Note that its data-loading cells currently use **hard-coded local Windows paths**, so update the two `pd.read_csv(...)` calls to point to your own copies of the files.

## Limitations and Notes

- `Supply_chain_work_in_progress.ipynb` is a work in progress, as its name says.
- The IoT results depend on assumed parameters (cost per device, reduction percentages, and late penalty) rather than measured data. Treat them as illustrative and replace them with real figures before using them for decisions.
- The simulation covers only loss-making `First Class` routes, while the classification models exclude `First Class` shipments, so the two parts analyze different slices of the data.
- Delay prediction relies mainly on location and shipping-mode features, so results may not generalize beyond this dataset's customer and order geography.
